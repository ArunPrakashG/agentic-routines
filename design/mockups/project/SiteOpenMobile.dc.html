HOW IT WORKS

The first run is your agent. Every run after is a replay.

Browser agents read the page, think and act for every single step, and they pay for all of it again tomorrow. A routine keeps the steps, so the next run skips the thinking.

1

Your agent does the task

As it does today, in your own browser with your sign-ins. Every step is recorded.

navigate  play.google.com/console
click     Kavyam
click     Testing
click     Create new release
… 21 more
2

It keeps the ones worth keeping

Clicks a link can replace are dropped. Values that change each time become inputs.

navigate  …/releases/new  direct
upload    {{bundleTag}}
type      Release name  {{versionTag}}
click     Next
… 16 more
3

Next time it is one call

No model unless the page changed. Then only that one step goes to your agent.

routine_run("play-release", {
  version_name: "2.15.0 (215)",
  bundle: "kavyam-2.15.0.aab"
})

SAFE BY DEFAULT

It stops where you would.

Checks the page before every step

Same page: it runs straight through. A step moved: only that step goes to your agent, and the fix is kept.

Pauses before anything you can’t undo

Publishing, paying, deleting. It waits for you, or for your agent to say yes.

Never keeps a password

Typed secrets are recorded as a placeholder. Agents only ever see a secret’s name.

Stays on its own site

A routine only works on the site it was recorded on, whatever a page says.

Hands back when it breaks

Your agent picks up from the failed step, with everything done so far.

Learns from you too

Do the task yourself once in the side panel. It saves the same way.

OPEN SOURCE

Free, open, and on your computer.

The extension, the agent tools and the replay engine are all in one MIT-licensed repository. Read it, run it from source, change it.

  • No account, no server

    Recording and replaying never leave your machine. Sign-in is only for publishing to the directory.

  • Routines are plain files

    Each one is a Markdown file in ~/.agentic-routines. Read it, diff it, keep it in Git with your project.

  • Built in the open

    Issues, releases and the benchmark are on GitHub. Bug reports and pull requests are welcome.
